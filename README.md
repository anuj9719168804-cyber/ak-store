## 🌐 Web panel + streaming (added)

One process now runs the bot, the admin panel and the file streamer (`python main.py`, one port).

**Set these (environment variables or Render/Docker settings):**

| Variable | Meaning |
|---|---|
| `WEB_URL` | Public https URL of your deployment. Without it the bot sends no web links. |
| `ADMIN_PASSWORD` | Panel password. Empty = panel disabled (there is no default password). |
| `STREAM_LINK_TTL` | Seconds a web link stays valid. Default `86400`, `0` = never expires. |
| `STREAM_CONCURRENCY` | Parallel Telegram transfers, default `8`. |
| `ADMIN_PANEL_PATH` / `STREAM_PATH` | URL layout, defaults `/admin` and `/file`. |
| `STREAM_SECRET` / `PANEL_SECRET` | Optional. Derived from `TOKEN` if unset. |
| `UPLOAD_ACCESS` | Who can store files by sending them to the bot: `admin` (default, stock Pro), `premium` or `all`. Non-admins can only store real files. |
| `LOG_CHANNEL_ID` | Optional. Panel actions and uploads are also posted to this channel (bot must be admin there). |
| `ACTIVITY_KEEP_DAYS` | How long the activity log is kept, default `90`. |

**How it works**
- When an admin stores a file (or uses `/genlink`) the reply also contains **Watch** and **Download** links for that DB-channel post. Links are HMAC-signed and expire, because plain Telegram links go through force-sub / credits / shortener while web links do not.
- The panel (`/admin`) has: dashboard, users (search, ban/unban), premium, admins, channels (read-only), stream-link maker, broadcast.
- Admins added from the panel or the bot are saved in MongoDB and reloaded on restart.
- The **Control Panel** button in `/start` (owner only, needs an https `WEB_URL`) logs the owner in without typing the password. Other admins use the password. It is owner-only because the panel can grant premium, which stock Pro allows only the owner to do.
- **Logs** page: panel logins, bans, premium/admin changes, broadcasts, link creation and file uploads.

**Maintenance scripts** (run from the project folder):
- `python -m scripts.backup_db` — MongoDB dump to `backups/` (needs `mongodump`; keeps the newest 7, see the file header for options)
- `python -m scripts.cleanup_expired` — removes expired premium users and old fsub/join-request records (fine to run daily from cron)
- `python -m scripts.create_admin 123456789` — add an admin directly in the database

A ready nginx config for VPS installs is in `nginx/filestore.conf`.

## 🆕 Files page, reminders, dedupe, 2FA, auto backup

**Files page (panel → Files)**: list, search (name / caption / message ID), sort (newest, most downloaded, largest), delete, copy bot link. Shows size and download count. Files uploaded *before* this update appear after the first download, or all at once via the **Scan DB channels** button (runs in the background).
Deleting removes the post from the DB channel, so every link to it stops working.

**Premium reminder**: each premium user gets ONE message when `PREMIUM_REMINDER_DAYS` (default 2) or fewer days are left, with a Renew button. Expired premium users are removed automatically (and told, if it expired in the last 3 days). Text is editable in `config.py` → `MESSAGES` (`PREMIUM_REMINDER`, `PREMIUM_EXPIRED`). Replaces running `scripts.cleanup_expired` by hand.

**Duplicate check**: sending a file that is already stored returns the old link and uploads nothing. Matching: Telegram `file_unique_id`, then real file name + exact size. Turn off with `DEDUPE_UPLOADS=false`. To re-upload on purpose, delete the old one from the Files page first.

**Panel security**: every POST form now needs a CSRF token (plus the old Origin check). Logout is a POST. Optional **2FA**: set `PANEL_2FA=true` and after the password a 6-digit code is sent to the owner on Telegram (valid 5 min, 5 tries). The owner's Telegram "Control Panel" button login needs no code (Telegram already proves the account). It is env-only so nobody inside the panel can turn it off. Make sure the owner has started the bot, otherwise nobody can log in with the password.

**Auto backup**: every `AUTO_BACKUP_HOURS` (default 24, `0` = off) the bot dumps MongoDB and sends the `.tar.gz` to the owner. `/backup` (owner) does it now. Uses `mongodump` if installed, otherwise a built-in export (the Docker image has no mongodump). The backup contains settings such as the shortener API key, keep the chat private.
Restore: `mongorestore --uri "$DB_URI" --db NAME <folder>/NAME` (mongodump backup) or `mongoimport --uri "$DB_URI" --db NAME --collection <name> --file <name>.jsonl` for each file (built-in export).

| Variable | Default | Meaning |
|---|---|---|
| `DEDUPE_UPLOADS` | `true` | Reuse the old link for a file that is already stored |
| `PREMIUM_REMINDER_DAYS` | `2` | Days before expiry for the reminder, `0` = off |
| `PREMIUM_CHECK_HOURS` | `6` | How often reminders / expiry cleanup run |
| `RENEW_URL` | `https://t.me/anujedits76` | Renew button link |
| `AUTO_BACKUP_HOURS` | `24` | Backup interval, `0` = off |
| `PANEL_2FA` | `false` | Telegram code after the panel password |

## 🔀 Added from Multi-FileStoreBot

- **Custom caption** — `/settings` → page 2 → **Caption**. A template is added under the original caption of every delivered file. Placeholders: `{file_name} {file_caption} {previouscaption} {size} {duration} {quality} {language} {username}`. Saved in MongoDB, survives restarts. Falls back to the plain caption if the result would pass Telegram's 1024-character limit. **Mode** button: *append* (default, template goes under the file's own caption) or *replace* (only the template is sent; put `{file_caption}` in it to keep the original text somewhere, like AK's custom caption). New placeholder `{type}` (Video / Audio / Document / Photo) next to `{year}`.
- **Custom thumbnail** — `/settings` → page 2 → **Thumbnail**. Send a photo (not as a file) and it is put on every video / document the bot delivers; **Remove** and **View** are there too. Telegram can't change a thumbnail on a plain copy, so those files are downloaded and uploaded again (files over 700 MB, other media types, or any failure are sent normally). Auto Quality uploads use it too instead of a generated frame. The image is converted to a 320 px JPEG under 200 KB and kept in MongoDB. Needs `ffmpeg` (already in the Dockerfile). The **Switch** button turns it ON/OFF without deleting the image.
- **Caption Cleaner** — `/settings` → page 2 → **Caption Cleaner** (ideas from AK Manager). Cleans the file's *own* caption and `{file_name}` before delivery; your Custom Caption is never touched. **Links**: off / remove (hyperlinks keep their text, plain URLs and t.me links go) / replace (every link becomes your own link). **@usernames**: off / remove / replace with your own @username. **Remove words** (one per line) and **Replace words** (`old => new`, one per line, applied last so a replacement may contain your @channel or link). **Numbering** (`1.` `1)` `1️⃣` `* 1` `- 1`, counted per delivery, handy for episode batches) and **Bullet** (🚀 🔥 📌 ⭐ 💫 ✨) in front of the final caption. **⚡ Clean all** is a one-tap preset (links + @usernames removed). Case-insensitive, max 30 entries per list, works on the text between HTML tags so formatting and links never break. Also adds `{year}` to Custom Caption. Not applied to multi-bots (`/my_bots`).
- **File Buttons** — `/settings` → page 2 → **File Buttons**. URL buttons under every delivered file, one per line: `[Join Channel][buttonurl:https://t.me/mychannel]`, add `:same` at the end of the url to share the previous button's row. Max 8. They are added under the file's own buttons; "disable button" only drops the original ones.
- **Safe delivery** — if Telegram refuses a customised caption or button (for example a bad button url), the file is sent again with its own caption and buttons, so a setting can never cost a user their file.
- **`/custom_batch`** (owner/admins) — one link for any set of DB-channel posts, consecutive or not. Send posts one by one, then `/done` (`/cancel` aborts). The list is stored in the `custom_batches` collection; the link only holds a short key (Telegram limits `start` to 64 characters).
- **New-user log** — every first `/start` is written to the activity log (panel → Logs) and posted to `LOG_CHANNEL_ID` if set.
- **Link log** — every link made with `/genlink`, `/batch`, `/nbatch` or `/custom_batch` is written to the activity log (who, which command, the link) and posted to `LOG_CHANNEL_ID` if set.
- **`{bot_mention}`** — new placeholder for the START message (becomes `@yourbot`), next to `{first} {last} {username} {mention} {id}`.
- **Command menu** — Telegram's `/` menu is set on start: user commands for everyone, admin commands for each admin, owner commands for the owner. Admins added later get their menu after the next restart.
- **Force-sub mode toggle** — `/settings` → Force-sub → **Toggle Request / Join mode**: switch a channel between join-request and normal join without removing it. A channel that is also listed in `config.py` `FSUBS` goes back to the config value after a restart.
- **Tutorial button on/off** — `/shortner` → **Tutorial button**: hide or show the Tutorial button on the verification screen. Saved in MongoDB.
- **New channel ids** — `main.py` widens Pyrogram's channel-id limit so very new channels (`-1003…`) resolve.
- **Quieter logs** — pyrogram, pymongo, motor and hypercorn log warnings only.
- **Shortener hardening** — the shortener call no longer freezes the bot (it ran blocking, with no timeout, inside the event loop); links are URL-encoded, cached per shortener (changing domain/key no longer returns old links, cache is size-capped), plain-text shortener replies are accepted, the API key is masked in `/shortner` and the message you send it in is deleted.
- **Texts and photos are saved** — Start/FSub/About/Channels/Reply texts and the Start/FSub photos edited from `/settings` are stored in MongoDB and survive restarts (before, they reset on every redeploy). A photo you send is stored as a Telegram file id instead of a local file. Fixed on the way: the Channels text overwrote the About text, `http://` photo links were rejected, and error paths called a non-existent `client.logger`.

## Shortener bypass detection

Works in the main bot and in every worker bot.

- Verifying faster than `BYPASS_MIN_SECONDS` (default 45s) counts as a bypass: the session is cleared and the user gets a strike.
- After `BYPASS_MAX_STRIKES` (default 3) strikes the user is auto-banned (`BYPASS_AUTO_BAN=true`). A successful verification resets the strikes.
- Verifying later than `VERIFY_MAX_SECONDS` (default 240s) = timeout, a new link is needed.
- Worker bots use a one-time token per verification (`start=vf_<token>`), so the old open `?start=verify` link no longer works.
- Every bypass / auto-ban is written to the activity log and posted to the log channel.


> **VPS / panel hosts:** `bash start.sh` installs the requirements and starts the bot in one command.

| Feature | How to use |

| **Referral + daily bonus** | `/refer` (invite link) and `/daily`. Credits and limits in `.env`. The inviter is paid when the invited person gets their first file (`REFERRAL_QUALIFY=file`, default), completes a verification (`verify`) or joins (`join`, easiest to farm). |
| **Gift codes** | `/gencode credits 20 50 7d` (or `premium 30 10 0 MYCODE`), users send `/redeem CODE`. One use per person, limited people, optional expiry. `/codes` lists, `/delcode` switches off. |
| **Credit ledger** | Every credit *grant* (verify, daily, referral, payment, code, admin) is logged. `/ledger <user id>` shows where a user's credits came from. Spending is not logged. |
| **Search + inline** | `/search words` and `@bot words`. Enable inline once in @BotFather (`/setinline`). `SEARCH_ACCESS` controls who may search. |
| **Auto reactions** | The bot reacts with a random emoji to every command in private chat. Turn off with `AUTO_REACT=false`. |
| **/help and /info** | `/help` lists the commands (admins also see the admin ones). `/info` shows the user's Telegram details, plan, credits and when they first used the bot. |
| **Auto-batch** | `/autobatch on` — when 2+ qualities (480p, 720p, 1080p ...) of the same title/episode are posted by hand in a DB channel, one batch link is made and sent to the owner. `/autobatch 45` sets the wait (seconds); `AUTO_BATCH_WINDOW` is the default. Off by default. |
| **Auto-split (files over 2 GB)** | On by default. A stored file above 2000 MB is cut into parts of at most `AUTO_SPLIT_MB` (default 1900), uploaded to the same DB channel, and **one batch link** delivers all parts. Videos are cut with ffmpeg stream copy (no re-encode, every part plays on its own, named `Movie.4K.part01.mkv`); any other file is split into raw `name.zip.001`, `.002` ... (join with 7-Zip or `cat name.zip.* > name.zip`). Quality copies that are over 2 GB are split the same way. `/autosplit on|off`, `/gensplit` for a file that is already stored. Needs about 2.2x the file size free on disk while working; sources above `AUTO_QUALITY_MAX_MB` (default 4000) are skipped. **4 GB without splitting:** put the string session of a Telegram **Premium** account in `PREMIUM_SESSION` (`.env`). That account (it must be admin of the DB channel) then uploads the big files and quality copies, so anything up to `PREMIUM_MAX_MB` (default 3900) stays ONE file; above that it is split. If the session is empty, not Premium or fails, the bot uploads and splits at 2 GB as before. Use a separate account and keep the session secret. Note: `/autobatch` may also react to files that the Premium account posts, so keep it off when using auto-quality. |
| **Auto-quality (144p → 4K)** | `/autoquality on` — store one video (say a 4K file) and the bot re-encodes it with ffmpeg into every *smaller* quality (`144p 240p 360p 480p 720p 1080p 1440p`; never upscaled), uploads them to the same DB channel and sends **one batch link** with all qualities. The normal single link still comes instantly; the batch link follows when encoding is done. `/autoquality set 144p,360p,720p` picks the qualities, `/genquality` does it for a video that is already stored. Env: `AUTO_QUALITY`, `AUTO_QUALITY_LIST`, `AUTO_QUALITY_PRESET`, `AUTO_QUALITY_THREADS`, `AUTO_QUALITY_PARALLEL`, `AUTO_QUALITY_MAX_MB`. Needs ffmpeg (Docker image has it; on a VPS run `apt install ffmpeg`). **Upscale:** `/autoquality upscale 1080p,1440p,4K` also enlarges *small* videos (e.g. 720p → 1080p/2K/4K) with the src bot's `/mastervideo` filter chain (Lanczos + denoise + CAS sharpen); it is not AI, so it looks bigger and cleaner but adds no real detail. Max enlargement `AUTO_QUALITY_UPSCALE_MAX_FACTOR` (default 4x); `/autoquality upscale off` disables it. Subtitles are not copied into the small MP4s. Off by default. |
| **Maintenance mode** | `/maintenance on` — everyone except admins gets an "under maintenance" notice (messages, buttons, inline search). `/maintenance off` to end it. |
| **Duplicate files** | Uploads through the bot were already de-duplicated (`DEDUPE_UPLOADS`). New: a file posted by hand in the DB channel triggers a warning (or removal with `DUPLICATE_DB_POST=skip`). |
| **Stats** | Panel *Analytics*: daily graph, top files, top links, orders. Dashboard shows today's numbers. |
| **Owner alerts** | DB / force-sub channel access lost, worker token revoked, bypass spike, failed backup, unfulfilled payment: the owner gets a message. (Daily auto-backup already existed: `AUTO_BACKUP_HOURS`.) |
